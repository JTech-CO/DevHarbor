# P3 구현 결과 — 승인·기록·복구 기반

2026-09-27. 승인 broker, WPF 최종 확인, SQLite write-ahead 원장, 프로세스 중단 후 상태 대조, 샘플 보관·복원 구현과 자동 검증을 완료했다. **실제 캐시 정리 출시 게이트와 사람의 수동 승인 수용 검증은 미완료**다. [ADR-004](../architecture/ADR-004-approved-workflow.md)에 실행 범위와 위협 모델을 기록했다.

## 구현

- 저장소 지도의 `정리·복구`에서 선택한 저장소의 실행 차단 근거를 표시한다. pip/uv도 현재는 차단한다.
- `샘플로 승인 흐름 확인`은 앱 전용 위치에 68-byte 샘플을 만든다. 불변 계획을 생성한 뒤 경로·크기·복구 방법·만료를 확인하고, 체크와 명시적 클릭을 모두 거쳐야 이동한다.
- 사용자의 SID·세션·broker·계획 digest에 묶인 단회 승인이다. 만료·위조·재사용·대상 변경은 거부한다. 외부 `approved=true` 입력은 없다.
- SQLite intent를 먼저 확정하고 P1의 상대 핸들 rename을 사용한다. 결과 쓰기가 실패하면 상태 확인이 필요하다고 알린다.
- 이력에서 별도 승인 후 복원한다. 원래 이름이 있으면 보존하고 다른 파일명으로 새 승인을 받을 수 있다.
- 다시 실행하거나 `상태 다시 확인`을 누르면 원장과 파일을 대조한다. 대조는 자동 이동·재실행을 하지 않는다. 불명확한 파일은 직접 확인 대상으로 남긴다.
- 중지/창 닫기는 취소를 요청한다. 이미 완료한 이동은 완료로 기록하며 기록이 확정될 때까지 창을 닫지 않는다.

## 검증 증거

환경: Windows 11 x64, NTFS, .NET SDK 10.0.401. 자동 검증은 임시 앱 전용 fixture에만 쓰며 실제 도구 캐시는 변경하지 않았다. 새 패키지 lock과 전체 솔루션 빌드에서 경고/오류 0건을 확인했다.

| 검증 묶음 | 통과 |
|---|---:|
| 도메인 계약 | 12/12 |
| Windows 파일 경계 | 34/34 |
| 발견·집계 | 24/24 |
| 저장소 지도 WPF | 6/6 |
| P3 승인·원장·중단·화면 | 38/38 |
| 합계 | 114/114 |

P3 자동 증거: [p3-windows-2026-09-27.json](../evidence/p3-windows-2026-09-27.json). 각 실행의 원본 fixture·PNG·결과는 ignored `artifacts/p3`에 남긴다. 개인 경로가 들어가는 DB/화면 PNG를 저장소에 포함하지 않는다.

P3 검사는 승인 위조·재사용·다른 broker/SID·만료·세션 종료·변조 계획·직전 파일 변경, 동시 실행/대조, 실행 전 취소/intent 후 취소/rename 후 취소, 결과 쓰기 실패·실제 SQLite 쓰기 잠금·DB 손상·DB 유실, 복원 충돌과 새 파일명 승인, 손상 receipt, 샘플/상태 루트 junction 거부를 포함한다. 미해결 intent가 남았을 때 새 실행을 차단한다.

별도 자식 프로세스를 `approved`, `before-intent`, `intent`, `moved`, `before-result`, `recorded`에서 종료하고 새 프로세스로 대조했다. 보관/복원 각 6개, 총 12개 시나리오에서 자동 이동 없이 payload가 한 위치에 보존되고 SHA-256이 일치했다. 이는 프로세스 종료 증거이며 재부팅·전원 손실 증거는 아니다.

writable mapping fixture에서는 이동이 `NotApplied:Busy`로 차단됐다. 다른 프로세스/매핑 생성 방식 및 pip/uv 실행 중 경합을 전수 검증하지 않았으므로 D4를 해제하지 않았다.

실제 WPF XAML을 RenderTargetBitmap으로 렌더링해 보관 승인·복원 승인·이력 화면의 경로 줄바꿈, 미승인 기본 상태, 만료 시 버튼 차단, 복원 가능 상태, 바인딩을 확인했다. 이 검사는 실제 사람의 키보드/마우스 확인·접근성·창 닫기 체감 검증을 대신하지 않는다.

## 남은 출시 조건

| P1 인수 조건 | 현재 결과와 다음 작업 |
|---|---|
| D1 Shell handoff·휴지통 보장 | backend 미연결. disabled/quota-full 실제 검증 미실시. 계속 false |
| D2 신뢰된 사람 승인 | 제한된 앱 내부 broker·자동 거부 검증 구현. 실제 사람 UI 수용 및 접근성 확인 필요 |
| D3 durable 원장·재시작 대조 | 12개 프로세스 종료 지점 통과. 전원 손실·재부팅·여러 항목 배치 지원은 미검증 |
| D4 writable mapping·live 사용 상태 | 한 fixture의 Busy 거부 관찰. 실제 pip/uv 사용 상태와 삭제 범위 검증 전 차단 |
| D5 큰 파일·폴더 변경 | 확장하지 않음. P1 제한 유지, 제품에서는 앱 생성 샘플 한 개만 허용 |

실제 캐시 재생성에 필요한 원본 출처·인증·네트워크 조건을 검증할 수 없으므로 재생성 명령도 제공하지 않는다. UI에서 미검증 사유를 보여준다. 따라서 실제 재다운로드의 인증 오류·오프라인 오류 처리 완료로 표시하지 않는다. 이 범위는 P3 기획의 “범위가 검증된 adapter만 활성화” 규칙을 따른다.

## 실행 및 사람이 확인할 절차

```powershell
./scripts/Start-DevHarbor.ps1
./scripts/Validate.ps1 -WindowsIntegration
```

1. `정리·복구` → `샘플로 승인 흐름 확인`. 대상이 앱 전용 sample.txt인지 확인하고 취소한다. 파일 이동이 없어야 한다.
2. 새 샘플 계획에서 체크 후 명시적으로 승인한다. 이력에 보관 중이 나타나고 공간 확보량이 0임을 확인한다.
3. 보관 중 행 → `선택 파일 복원 검토` → 대상 확인·별도 승인. 복원 완료 상태를 확인한다.
4. 승인창을 2분 이상 유지했을 때 만료되고 클릭할 수 없는지, Tab/Space/Enter/Escape 조작과 텍스트 읽기가 가능한지 확인한다.
5. 계획 창/실행 창 닫기 및 중지 요청을 확인하고 다시 열었을 때 이력이 유지되는지 확인한다. 전원 강제 종료는 이 절차에 포함하지 않는다.

수동 결과 기록: **미실시**. 성공/실패·OS·표시 배율·입력 방식·관찰 결과를 추후 추가한다. 상태 파일은 `%LOCALAPPDATA%/DevHarbor/Workflow`에 보존된다. 정리·복구 창에서 생성한 샘플도 자동 삭제하지 않는다.

P4는 읽기 전용 MCP와 계획 검토 계약을 진행할 수 있다. P3의 미완료 출시 조건을 통과하지 않은 실제 변경 API/자동 승인 연결은 계속 금지한다.
