# DevHarbor 마일스톤

2026-09-25 · P0 완료, P1 경계·격리 기반 구축 및 평가 완료. 제품 삭제 게이트는 NO-GO, 다음 단계는 P2 읽기 전용이다. 단계 완료 여부는 산출물과 검증 증거로 판단한다.

| 단계 | 목적 | 선행 조건 | 완료 기준 | 예상 범위 |
|---|---|---|---|---|
| [P0](P0-foundation.md) | 제품·계약·개발 기반 | 없음 | 지원 범위/정책/ADR, 빌드 및 정책 검증 성공 | 2–4일 |
| [P1](P1-windows-boundary.md) | Windows 변경 안전성 | P0 | 경계→변경 경합 방지, 실패 시 변경 없음 증명 | 1–2주 |
| [P2](P2-readonly-product.md) | 읽기 전용 제품 | P0, P1 경계 계약 | 실제 도구 경로 탐색·공간 화면·측정 정확성 | 1–2주 |
| [P3](P3-approved-cleanup.md) | 승인·기록·복구 | P1, P2 | 신뢰된 승인 및 장애 복구 통합 테스트 통과 | 2–3주 |
| [P4](P4-agent-and-models.md) | MCP·모델 세션 | P2, 변경은 P3 | 3개 클라이언트 및 언로드 계약 검증 | 1–2주 |
| [P5](P5-release.md) | Windows 베타 배포 | P0–P4 | 서명 배포·설치/업데이트/복구 QA | 1–2주 |

기간은 개발자 1명의 초기 추정이고 일정 약속이 아니다. P1이 막히더라도 P2 읽기 전용 구현은 검증된 읽기 계약 안에서 진행할 수 있다. 삭제 기능의 출시 게이트는 우회할 수 없다.

공통 완료 규칙:

- 문서의 가정과 실제 지원 capability를 구분한다.
- 정상 동작뿐 아니라 보호/오류/취소 시나리오를 검증한다.
- 사람이 확인하지 않은 UI나 원격 CI는 완료로 표시하지 않는다.
- 라이선스·개인 경로·토큰·fixture·SDK를 배포에 섞지 않는다.
- P0에서 P5 전체가 구현되었다고 표시하지 않는다. 현재 요청은 기획 후 P0 실행까지를 완료 단위로 잡는다.
