# DevHarbor — Windows 개발 환경의 저장소 관리

2026-09-25 · 독립 제품 기획 v0.1

## 제품 정의

DevHarbor(데브하버)는 Windows 개발자와 로컬 AI 사용자가 도구별 저장소의 점유량, 재생성 비용, 변경 이력을 이해하고 직접 정리하도록 돕는 데스크톱 앱이다. 슬로건은 **“개발 공간에 근거를 더하다.”**

이름은 개발 도구와 산출물이 모이는 항구를 뜻한다. 상표·도메인 가용성은 아직 검토하지 않았다. 브랜드·아이콘·화면·라이선스 운영은 독립적으로 설계한다. 저장소는 https://github.com/JTech-CO/DevHarbor 이며 기존 MIT 라이선스를 유지한다. 상세 실행 계획은 [마일스톤 로드맵](milestones/README.md)을 따른다.

핵심 사용자는 여러 Python/Node 프로젝트, 로컬 모델, Docker Desktop을 함께 사용하고 저장 공간 부족을 반복 경험하는 사람이다. 첫 사용의 성공 기준은 “어느 도구가 어디에 저장했고, 무엇을 정리하면 어떤 비용으로 돌아오는지”를 설명할 수 있는 것이다.

## 독립적인 구성과 차별화 방향

다른 제품에 없는 기능이라는 시장 검증 주장은 하지 않는다. 다음은 이 제품이 집중할 설계상의 차별점이다.

| 집중점 | 사용자에게 제공할 결과 |
|---|---|
| Windows·WSL 환경 구분 | C/D 드라이브, 네이티브 도구, WSL 배포판, Docker 엔진을 구분한 저장소 지도 |
| 재생성 비용 표시 | 다시 받을 용량, 인증 필요, 빌드 필요, 버전 고정 가능 여부를 보여줌. 모르는 소요 시간은 추측하지 않음 |
| 공유 저장소 인식 | HF blob·하드링크·Docker layer를 논리 크기와 물리 점유로 나눠 설명 |
| 계획과 결과의 대조 | 요청된 대상, 실제 처리한 대상, 건너뛴 이유, 관측된 여유 공간 변화를 한 작업 기록으로 연결 |
| 프로젝트 맥락 | 전역 캐시와 프로젝트 환경/체크포인트를 구분하고, 프로젝트별 재구성 근거 확인 |
| 제한된 에이전트 협업 | 에이전트는 조회·계획 요청, 사용자는 앱에서 정확한 대상과 복구 방식을 승인 |

초기 제품에서 “RAM 최적화”, 건강 점수, 전체 디스크 원클릭 청소를 중심 메시지로 쓰지 않는다. 메모리 영역은 모델의 로드 상태와 도구가 제공하는 언로드 기능을 설명하는 보조 기능이다.

## 브랜드와 화면 구성

차분한 작업 도구의 인상을 기본으로 한다. 잉크색(#16212B), 청록색(#147D78), 밝은 배경(#F4F7F8)을 기본 팔레트 후보로 두고 주의는 호박색, 실행 오류는 붉은색을 사용한다. 색만으로 상태를 구분하지 않는다. Windows 시스템 글꼴을 기본으로 하고 독립적인 아이콘을 제작한다. 아직 실제 디자인 시안이나 접근성 대비 검증은 수행하지 않았다.

원형 휠 대신 정렬 가능한 표, 도구별 가로 막대, 계획 전후 비교를 우선한다. 큰 모델 이름, 긴 경로, 여러 드라이브를 읽기 쉽도록 설계한다.

| 화면 | 핵심 구성 |
|---|---|
| 저장소 지도 | 드라이브/실행 환경 필터, 도구별 점유, 마지막 스캔, 미측정 범위 |
| 정리 계획 | 후보·제외 이유·재생성 비용·실제 회수 추정, 변경 방식별 묶음 |
| 작업 기록 | 요청/승인/실행/부분 실패/복구 상태와 항목별 영수증 |
| 모델 세션 | 도구별 로드 상태, RAM/VRAM 관측, 앱에서만 가능한 언로드 |
| 연결과 규칙 | MCP 연결, 포함 저장소, 제외 경로, 네트워크 검증 설정 |

상태는 다음과 같이 표현한다.

- **다시 생성 가능:** 정확한 재생성 근거와 조회 시각을 함께 표시.
- **확인 필요:** 출처·복원 경로 불명확, 자동 선택 및 MCP 정리 불가.
- **보관 대상:** 사용자 산출물·데이터베이스·인증 정보, 변경 기능에서 제외.
- 별도 배지: 사용 중, 측정 불가, 재다운로드 필요, 인증 필요.

“다시 생성 가능”과 “휴지통에서 원본 복원 가능”은 별도 속성이다. 사용자가 선택하더라도 제품이 보호하는 저장소에는 범용 강제 삭제 버튼을 제공하지 않는다.

## 사용자 여정

1. 설치된 도구와 설정이 가리키는 저장소를 읽기 전용으로 발견한다. 전체 디스크 재귀 탐색은 기본 동작이 아니다.
2. 도구별 크기와 미측정 범위를 확인한다. 사용자 지정 경로를 추가하면 그 경계 안에서만 스캔한다.
3. 항목을 선택하면 정리 계획을 생성한다. 사용자 파일과 알 수 없는 형식은 제외 이유를 보여준다.
4. 신뢰된 앱 확인창에 대상, 크기, 삭제 방식, 복구 방식, 재생성 비용을 표시한다. 승인 유효기간은 초기 3분으로 제안한다.
5. 승인된 계획의 파일/객체 식별자를 다시 검증한다. 대상이 바뀌면 실행하지 않는다.
6. 실행 결과를 작업 기록으로 남긴다. 휴지통 이동량을 디스크 회수량으로 표시하지 않는다.
7. 원본 복원 또는 재생성 안내를 제공한다. 원래 위치에 새 파일이 있으면 보존하고 별도 이름으로 복원한다.

## MVP와 후속 구성 요소

| 구성 요소 | MVP | 후속 |
|---|---|---|
| 저장소 탐색기 | pip/uv/npm/Ollama/HF/Docker 읽기 | NuGet, Gradle, Conda, LM Studio, WSL 내부 |
| 근거 판정기 | 공급업체 계약 및 검증된 형식, unknown은 변경 불가 | 정확한 registry artifact 검증·출처 그래프 |
| 용량 계산기 | 논리량/할당량/측정 불가, 중복 방지 | 여러 도구 간 공유 blob 표시 |
| 계획 엔진 | 단일 사용자, 불변 계획, 만료·단회 승인 | 복수 계획 충돌 처리, 프로젝트별 예산 |
| Windows 변경 계층 | 검증된 범위의 제한된 캐시 adapter | 폴더 단위 작업, 다중 볼륨, 추가 파일시스템 |
| 복구 원장 | 선기록·항목별 결과·휴지통 참조·재생성 안내 | 격리 만료 및 자체 소유 항목만 비우기 |
| MCP | 새 이름 `devharbor_overview/items/plan/plan_status`, 읽기와 계획 | 복구 안내 조회, 연결 자동화 |
| 메모리 | 모델 상태 조회, 검증된 Ollama 언로드 | LM Studio/ComfyUI, GPU별 지표 |

MCP에 `approve` 도구나 임의 shell 실행 도구를 제공하지 않는다. 계획은 앱이 보유하고 사용자가 앱에서 승인하면 executor가 실행한다. 에이전트는 결과만 조회한다. 이 구조가 동일 사용자 권한의 악성 로컬 프로그램까지 격리해 준다고 주장하지 않는다.

MVP에서 범용 언인스톨러, 레지스트리 청소, Docker volume/container 제거, VHDX 압축, WSL 종료, 사용자 파일 중복 삭제는 제외한다.

## 구현 방향

Windows 11 x64·로컬 NTFS·현재 사용자 계정을 첫 검증 범위로 둔다. C#/.NET 10 LTS + WPF + SQLite를 선택하며 결정 근거는 ADR-001에 기록한다. 초기 안전성 실험은 PowerShell Add-Type으로 수행했고, 제품 코드는 SDK 기반 빌드로 분리한다.

모듈 이름은 `DevHarbor.Desktop`, `Domain`, `Discovery`, `Evidence`, `Windows`, `Execution`, `Ledger`, `Mcp`로 제안한다. UI/MCP가 삭제 API를 직접 호출하지 못하게 한다. 현재 실험 코드는 이 모듈의 완성 구현이 아니다.

기본 엔진은 사용자 권한으로 동작한다. 권한이 필요한 경로는 미측정/미지원으로 남기며 상주 관리자 서비스는 도입하지 않는다. 레지스트리 조회 등 외부 요청에는 경로/토큰이 불필요하게 포함되지 않도록 한다.

## 검증 결과와 다음 개발 게이트

이번 실험에서 22개 자동 검사와 실제 테스트 파일의 휴지통 왕복을 통과했다. 상세 증거와 한계는 [WINDOWS_SAFETY_REPORT.md](WINDOWS_SAFETY_REPORT.md)에 기록했다.

다음 우선순위:

1. **경계와 Shell 작업 연결:** 검증 핸들을 닫은 후 Shell 작업이 수행되기까지의 경합을 해결하고 공격적 파일 교체 테스트 추가. 해결 전 실제 사용자 파일 변경 기능 금지.
2. **복구 원장:** SQLite 선기록·원자적 상태 전이·중간 크래시 복구, 복수 항목/재부팅 검증.
3. **실제 승인 경계:** WPF 확인창과 사용자 ACL 제한 IPC, MCP의 승인 위조·재사용·동시 요청 통합 테스트.
4. **읽기 전용 세로 구현:** pip/uv 저장소 탐색 → 지도 UI → 근거 표시 → MCP 조회.
5. **제한 정리 베타:** 승인 범위 밖을 건드리지 않는 adapter만 추가. 벤더 purge와 원본 복원 가능성을 혼동하지 않음.

기존 6–12주 규모 추정은 기능을 좁힌 MVP의 참고값이며, 위 안전성 게이트 통과 전 출시 날짜를 확정하지 않는다. 수익화·가격·계정 시스템은 초기 안전성 검증에 포함하지 않는다.

성공 지표는 잘못된 대상 변경 0건, 승인 밖 변경 0건, 복구 가능으로 표시한 작업의 복원 성공률, 과대 보고 없는 공간 계산이다. 분석 데이터는 우선 로컬 실험에서만 수집하고 실제 사용자 텔레메트리는 별도 제품 결정으로 남긴다.
